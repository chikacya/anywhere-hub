## 审阅问题处理

普通 MITM 关注以 moduleVersion 为基线，sourceVersion 单独用于 catalog 比较。首次从旧脚本关注迁移时，原源版本相同则建立模块基线，原源版本已变化则保留待确认状态。旧基线没有历史模块 hash，无法恢复迁移前仅模块变化的精确历史，不宣称补齐该历史。
开屏关注保存 scope；当前草稿与 scope 分离，新增/移除草稿应用不误报更新。旧 id:revision 基线尽量恢复原 scope；空范围旧基线迁移不制造误报。修改关注范围需取消再关注，不自动声称 Anywhere 已更新。
目录刷新读取最新开屏 catalog，面板打开时延后；关闭面板再刷新。稳定 ID 保持，暂不可用项从编辑选择移除，但关注范围保留以便提示其规则变化。
相同搜索结果勾选时不重建列表；摘要更新不重绘背景 MITM 图标。选择/移除操作及步骤切换处理焦点。
开屏 ETag 和边缘缓存键使用最终输出 SHA-256，因此描述、模板或规则改变都会改变验证器。不存在的独立输出先返回 404，不再因构造 ETag 返回 304。代价是条件请求也需本地组装与散列；没有据本地耗时推断边缘 CPU。
路由模块预检路径已从 UI 移除，不再发生其异步失败跳批和模块大小错误；兼容 API 不删除、900000 字节保护不放宽。
