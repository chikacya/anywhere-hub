# MITM 应用选择 · 设计审阅 V1

2026-10-05。仅设计原型；未修改 public/ 或 src/，未接入 Hub 服务，未部署、未提交、未推送。

## 设计方向

延续实际 `public/styles.css` 的字体、颜色、卡片、圆角、蓝色按钮、底部导航与弹层。复用本地已分配的合集图标及现有独立插件图标。入口在 MITM 脚本列表，作为同一网格中的“应用开屏去广告”卡片；不增加顶层 Tab。合集入口可放在列表前部，其他独立脚本保持现有结构。

卡片沿用关注与更新状态，主操作“选择应用”；已有保存选择时“调整组合”。列表搜索同时命中应用名，找到组合入口；搜索词应在正式实施时带入选择面板。关注合集只追踪与已选范围有关的变化；新增应用默认不加入、不触发无关更新提示。

## 流程

1. 选择应用：默认空组合，搜索、全部应用/已选/共享服务筛选，单项勾选与清空。无规则条目禁选并说明原因；有域名覆盖缺口的条目显示“覆盖提示”。当前目录共有 397 条，其中 388 个可选应用、1 个共享服务、8 个无规则条目。
2. 桌面右侧展示我的组合和域名/规则/路由数量；手机保留底部已选摘要，详细冲突在下一步呈现。仅列表滚动，底部操作固定可见；全行点击、键盘勾选、Escape 关闭、返回保留选择。数量均来自审核目录，不代表广告效果。
3. 确认导入：列出组合及按实际选择产生的 .amrs/.arrs。不同路由动作应分别输出并一并导入，无配套路由不显示该文件。冲突只提示匹配的独立插件名称，不推断用户已安装、不自动排除应用；可返回调整。
4. 修改选择后重新导入，明确 Hub 不会直接修改 Anywhere 现有脚本。选择在浏览器本地保存；正式实施补齐“复制组合链接”和选择导入/导出为次级操作。分享链接只携带应用 ID 与目录版本，不携带私人配置。

## 审阅确认与补充（2026-10-05）

整体 UI 已获维护者认可。来源与转换说明直接放到合集大标题下方，不再藏在折叠项。添加“全选可用应用”（当前 388 项），默认仍为空；共享 AMDC 独立勾选，不由全选应用自动启用。

导入合同：提供可更新 HTTPS 订阅地址，不以本地文件作为主要入口。选择以稳定应用 ID 的规范编码进入链接，同一选择生成同一链接，不同选择产生不同链接；不需要用户账户或私人配置存储。链接表示固定选择范围，服务端返回最新审核版本的这些规则；上游新增应用不自动加入。修改选择生成新的订阅地址，现有 Anywhere 条目需手动处理。正式实施时验证编码、长度、旧选择兼容和路由伴随链接。

Anywhere 当前本地源码单个 MITM RuleSet 上限 10,000 条；全选应用 500 个操作，包含 AMDC 时 501 个，均低于上限。该事实仅证明数量约束；全选模式的设备功耗、稳定性和实际去广告效果没有实机结论。

## 最新分类决策

按维护者要求移除“共享服务”界面分类，AMDC 作为“阿里系”的普通可选条目展示，也出现在全部列表。全选可用条目包含 AMDC，当前 389 项、501 个 MITM 操作；原始源档案的 shared 标记仅保留作溯源，不决定界面分类。

Worker 设计约束：本地预先生成审核片段，运行时只按 ID 组装；同一选择规范化为相同地址，以“审核产物版本 + 规范选择 + 产物类型”作为缓存键；不为用户分配 Worker 或持久化整份私人文件，不在刷新时抓取与翻译上游。普通 Cache API 缓存命中不应被当作免除 Worker 请求配额。上线前验证无缓存的全选 CPU、响应大小、缓存命中以及整站请求预算，当前没有线上负载实测结论。
